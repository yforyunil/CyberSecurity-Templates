## 3. Change Types
| Type | Description | Approval |
|---|---|---|
| Standard | Pre-approved, low risk, repeatable | Pre-authorized |
| Normal | Planned, assessed | CAB |
| Emergency | Urgent to restore service/mitigate threat | ECAB, retrospective review |

## 4. Change Lifecycle
1. Request (RFC)
2. Classification & risk assessment
3. Security & impact review
4. Approval (CAB)
5. Scheduling & communication
6. Implementation
7. Testing / validation
8. Backout (if failed)
9. Post-implementation review
10. Closure & documentation

## 5. RFC Required Fields
- Requester, date, system(s) affected
- Description and business justification
- Risk and impact assessment
- Test evidence
- Implementation plan and window
- Rollback plan
- Approvers

## 6. Security Requirements
- Security review for changes to production, network, identity, or data flows
- Segregation of duties between developer, approver, and deployer
- Configuration baselines updated after change

## 7. Change Advisory Board (CAB)
Membership, meeting cadence, quorum, decision criteria.
